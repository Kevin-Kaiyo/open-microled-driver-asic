# 39MOS PWM robustness experiments

This is a separate 100 µA display-PWM experiment, reusing the selected r5 full
nominal-RC macro and its original synthetic LED model. It does not reuse the
current-range/6MOS or NRZ receiver contract.

- Run through the project `.venv`; `ngspice` and `iverilog` must be installed.
- Frozen inputs, exact decks/logs and SHA-checked gzip raw remain in
  `build/pwm-robustness/20261024/`. Restore the corresponding prior Release
  inputs if the original r5 selected run is absent.
- Compact evidence lives in `evidence/pwm-robustness/20261024/`; plots and the
  Chinese chapter are generated by `report.py` and `topology_figure.py`.
- The PWM runner takes `/tmp/open-microled-ngspice.lock` exclusively. It never
  starts parallel ngspice processes itself.

Completed run identities are immutable. `--reuse` accepts identical decks, or
reuses an older electrical run with unchanged circuit/stimulus but a smaller
terminal inventory **without upgrading that inventory**. A changed circuit or
stimulus requires a new case/revision name. Stimuli are generated in staging,
so rejection cannot overwrite existing RTL events/logs.

The early terminal-inventory expansion (five pairs to six, including VGB)
retained byte-identical original attempts before a rerun. See
`attempt-preservation-audit.json` and the final identity migration audit. A
renamed revision retains its original executed result record and deck. Plot
CSVs are derived views, not the canonical raw evidence.

The two filter locations are materially different:

1. Legacy `filtered` cases place R/C at die ports, with the capacitor returned
   to die VSS. This is a local die/package-port hypothesis, not PCB placement.
2. `board100n` keeps the same 100 Ω / 100 nF, but places R and C before package
   R/L and returns the capacitor to board ground.

The ±20% current excursion and 5 µs recovery lines are exploratory comparison
budgets. They are not a user-approved product specification. Startup's original
20 µs external-fault assumption and all existing current/charge guards are
retained. Circuit failures, numeric probes and rejected candidates remain
visible. Terminal-voltage inventories are not reliability qualification.

```sh
.venv/bin/python scripts/pwm_robustness/run.py --suite dc --reuse
.venv/bin/python scripts/pwm_robustness/run.py --suite transient --reuse
.venv/bin/python scripts/pwm_robustness/run.py --suite selected --reuse
.venv/bin/python scripts/pwm_robustness/run.py --suite strong --reuse
.venv/bin/python scripts/pwm_robustness/run.py --suite board --reuse
.venv/bin/python scripts/pwm_robustness/run.py --suite summarize
.venv/bin/python scripts/pwm_robustness/report.py
.venv/bin/python scripts/pwm_robustness/topology_figure.py
```

## Small-input restoration on another computer

Use a POSIX environment (macOS, Linux, or WSL), the repository Python environment
with NumPy, ngspice and Icarus Verilog. Restore only these milestone artifacts:

- `build/pwm-robustness/20261024/inputs/`: the eight frozen files
  `design.ngspice`, `sm141064.ngspice`, `dut.spice`, `microled.spice`,
  `pixel_pwm.v`, `pixel_safety.v`, `tb_safety.v`, `math.py`.
- `evidence/pwm-robustness/20261024/input-manifest.json` and the requested case
  JSON (the default smoke test is `dc_board100n.json`).
- The public repository scripts, including this folder and `scripts/safety/run.py`.

The small replay entry point checks every input hash, copies into a new empty
work directory, compiles the frozen RTL, regenerates absolute SPICE includes for
that machine, and runs the selected case. It does **not** call the historical
Oct15 `freeze()` loader, and needs neither old analog raw waveforms nor the old
full layout/PDK directory tree:

```sh
.venv/bin/python scripts/pwm_robustness/reproduce.py \
  --inputs build/pwm-robustness/20261024/inputs \
  --manifest evidence/pwm-robustness/20261024/input-manifest.json \
  --case-file evidence/pwm-robustness/20261024/dc_board100n.json
```

The verified local smoke replay used a fresh sibling directory and reproduced
`dc_board100n` with exactly 0 A difference. See `reproduction-check.json`.
The frozen model files are an electrical model set, not a full physical PDK.
A successful electrical replay creates no new DRC/LVS/GDS or silicon evidence.
