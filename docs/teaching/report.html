Reading Guide

怎样跟着这份报告学习

这份讲义按“整体框架 → 细节 → 验证 → 版图”的顺序组织。第一次阅读先把系统中的能量路径和控制路径区分开；第二次再对照源码核对每个参数。你不必先掌握 FPGA，也可以从计数器、比较器与帧边界理解 ASIC 的数字逻辑。

Part 01

先看整体系统

01整体架构：让一个数字设定变成 LED 电流

能说出整个项目的输入、处理环节和输出。

先把 ASIC 看成分工明确的系统。数字逻辑回答“什么时候开”，模拟驱动回答“开时流多少电流”，LED 的电气特性参与决定电压工作点。当前输出是仿真电流，不能直接标为实测亮度。Python 负责运行、桥接和检查；实际 PWM 来自 RTL，电流来自 MOS/LED 的 SPICE 求解。 条件：单像素；单向 digital→analog。

  • 用户设定 duty 与 enable，数字逻辑产生 PWM。
  • MOS current sink 决定导通电流，LED 模型决定电气工作点。
  • 当前跑通一条单像素 RTL → transistor → LED 电流路径。
  • 平均电流作为电气亮度代理，光学输出仍待测。
对照出处：设计系统图 runner

02现在与长期：先完成一个像素，再增加规模

分清当前交付范围与长期 ASIC 架构。

当前已经推进到 standalone 六 MOS analog cell：Magic DRC=0、Netgen unique match、GDS roundtrip 复核通过，七个 nets 全部 RC extraction 后完成配对电气回归。这只支持该 analog cell 与所选公开 deck 的结果。数字 PWM 的 synthesis/physical integration、pads/ESD、foundry signoff、硅片及光学实测仍未完成。FPGA 是未来外部 controller 候选，当前 RTL 使用 Icarus 执行。4×4 的 receiver、register map 与 pixel memory 尚未实现，先学习并完成这一个像素的完整接口责任。

  • 已跑通一个像素的 RTL → transistor → LED 电流路径。
  • Standalone analog cell 已有 MAG/GDS、DRC/LVS 与 RC 回归。
  • 下一步完成数字 physical integration、reference 与芯片接口。
  • 4×4 的通信和像素存储仍按后续独立阶段展开。

03四种量：数据、时间、电流与光

分清设定 code、PWM duty、导通电流与 optical brightness。

只改变 duty 时，理想情况下改变的是点亮时间，导通电流幅值由 reference/mirror 决定。平均电流近似等于时间比例乘导通电流，但真实边沿有电荷项。把电流转换为光还需要器件效率、温度、current density 和测量，这些尚未建模或测量。 练习：保持导通电流 100 µA，25% duty 的理想平均电流是多少？答案 25 µA；这只是预估，稍后用仿真积分核对。 条件：typical、27 °C、VLED=5 V、synthetic Vf=2.8 V。

  • duty 是数字设定，D 是一帧的高电平时间比例。
  • 导通电流由模拟 reference 和 current mirror 决定。
  • 保持脉冲幅度，改变脉冲宽度就是 PWM 调光。
  • 平均电流是电气代理，需要实测才能换算光学亮度。
对照出处：brightness proxy metrics

04把信号路径与电流路径分开看

在同一图上找出控制信号和真实导通电流路径。

Gate 控制与 drain/source 导电路径不是同一根线。VSENSE 为零伏电压源，用于读取 branch current，不在模型中额外产生压降。全开时还有 reference 支路电流，系统总耗电不能只用 LED current 表示。真实供电阻抗、pad、封装和互连都需要以后加入。 条件：ideal rails、ground、IREF；Phase 1 baseline 无走线 R/C。

  • 控制路径：数据 → PWM → gate selection。
  • 参考路径：IREF → XREF → bias → gate。
  • LED 电流路径：VLED → LED → XOUT → GND。
  • Vlogic、VLED 与 IREF 目前都是 ideal sources。

Part 02

慢慢读懂 PWM 数字逻辑

05先定义 clock、slot 和 frame

用时间轴读懂 PWM 的时间单位。

教学缩略图只用于手算，不是改变实际 RTL。PWM frequency 描述一帧重复的速率，clock frequency 描述数字计数的步速。1 MHz 与 256 是起始设计假设，不是由 MicroLED datasheet 推导出的最佳参数。最短非零脉冲为一 slot，也就是 1 µs。 练习：clock 改为 2 MHz 且仍为 256 slots，frame 多长？128 µs；频率 7812.5 Hz。此练习不改源码、不声称已验证。 条件：baseline 1 MHz / 256 slots。

  • Clock 每个 rising edge 推进一次状态；1 MHz 对应 1 µs。
  • Slot 是相邻时钟边沿之间的一格时间。
  • Frame 包含 256 slots，周期为 256 µs。
  • PWM 重复频率为 1 MHz / 256 = 3906.25 Hz。
对照出处：pwm.md RTL testbench

06counter 与 comparator 怎样生成 PWM

能按 slot 手算 PWM 输出，并对应到 RTL。

计数器寄存器保存“现在走到第几格”；组合比较器判断“是否还处于点亮范围”。零扩展 {1'b0,counter} 将 8-bit 计数值与 9-bit threshold 对齐。这里不用较复杂的通信知识也能读懂逻辑；后续接口只负责可靠地产生新的设定。 练习：用 8-slot 教学表、duty=3，写出输出：11100000。再回到真实 256-slot 代码。 条件：enable=1，帧内 active_duty 固定。

  • Counter 保存当前 slot 编号，范围为 0…255。
  • Comparator 判断 counter 是否小于 active_duty。
  • enable 为 1 且判断成立时，PWM 为高电平。
  • duty=64 时，高电平覆盖 slot 0…63。
对照出处：pixel_pwm.v

07为什么 duty 有 9 bits，counter 只有 8 bits

理解 exact off / exact full-on 两个端点的编码。

8 bits 能表示 0…255，不能表示 256。多一位用于全开端点，所以合法状态共 257 个；不能据此称为 512 级灰阶或 9-bit analog effective resolution。代码 clamp 的测试覆盖所有 255 个越界值。 条件：counter=0…255；duty 为 9-bit unsigned。

  • 8-bit counter 覆盖 256 个 slots。
  • 9-bit duty 用于同时表示 0 与 256 两个端点。
  • duty=255 仍有一个 off slot；256 为 exact full-on。
  • 257…511 饱和到 256，共 257 个合法状态。
对照出处：RTL rtl-selfcheck.log

08帧边界提交：让一次更新作用于完整一帧

区分 requested duty 与 active duty。

如果直接用帧中变化的 duty 作比较，当前脉冲可能被截短或重新打开。锁存把请求与正在执行的一帧分开。当前输入属于同一 clock domain，尚未实现异步通信的 CDC 或 handshake。多像素后会需要整帧 atomic commit，这是同一思想的扩展。 练习：在 counter=100 时把 duty 从 64 改为 192，当前帧会立刻变高吗？不会；下一 frame 才使用 192。 条件：输入满足同域时序假设；未证明物理 setup/hold。

  • Requested duty 是输入请求，active duty 是当前帧设定。
  • 在 frame boundary 才锁存 duty 和 enable。
  • 帧中更新不改变正在执行的脉冲。
  • 下一帧采用边界前最后的输入值。
对照出处：更新与 reset RTL

09reset 与 enable：两种不同的关断规则

预测 reset、disable 与恢复输出的时间。

reset 可以中断当前 frame，enable 的正常更新则等到下一 frame。同步 reset 之前，RTL 寄存器没有已定义的初始化值。当前不是安全保护关断设计：没有过流 comparator，也没有异步 fault path。逻辑仿真通过不等于综合后组合 PWM comparator 无毛刺，后续数字物理验证需要单独进行。 条件：rising-edge synchronous reset；未实现 fault feedback。

  • Reset 为高有效同步信号，在下一 rising edge 生效。
  • Reset 清除设定，释放后从 slot 0 开始新帧。
  • enable=0 在下一 frame boundary 提交 off。
  • 两种关断规则分别由 RTL testbench 检查。
对照出处：RTL pwm.md

10从执行后的 RTL 边沿到 SPICE 电压

理解 feed-forward 联动是怎样建立的。

逻辑 1 本身没有 3.3 V 的电气含义，bridge 显式加入这条假设。第一条已知 low 来自 500 ns reset，桥接把它向前延伸到 SPICE 0 ns，这是启动假设。10 ns 并非 standard-cell 测得的 slew，也不包含 pad、level shifter 或 drive strength。真正反馈联仿需要模拟检测改变 RTL 状态；当前只有单向 replay。 条件：10 ns slew、3.3 V amplitude；首个 frame=2.5 µs。

  • Icarus 执行 RTL，导出 time_ns,pwm 边沿记录。
  • Bridge 保留 timestamp，转换成 0 / 3.3 V。
  • 每个边沿用 10 ns 的有限 ramp 表示。
  • ngspice 求解 MOS 与 LED；当前联动是单向 replay。
对照出处：read_events / pwl_points bridge tests
Part 03

从模拟机制到器件选型

11Current mirror：先用 reference 求出 bias，再复制电流

理解 diode-connected reference MOS 与 output MOS 的分工。

Current mirror 复制的是 reference 定义的电流关系，不是无条件把任何 LED 电流锁死为 100 µA。XREF 把给定电流转换成所需 VGS。输出端 VDS 与参考端不同，PDK model 会包含由此产生的误差；当前未启用 mismatch。适合用这个最小电路学习 bias、工作区和非理想误差。 条件：1:1 W/L；external ideal IREF；无 cascode/feedback。

  • Diode-connected XREF 将 IREF 转换成 bias 电压。
  • XOUT 利用相近 gate-source bias 复制电流。
  • 相同 W/L 对应 nominal 1:1 mirror。
  • 足够 headroom 与器件匹配是近似恒流的前提。
对照出处：pixel_driver.spice COCOA §5.3

12Headroom：LED 占用电压后，MOS 还剩多少余量

用节点电压解释为什么降低供电会掉电流。

MOS 维持近似恒流需要最低 compliance voltage，常称 headroom。长沟道近似可用 VDS ≥ VGS−VTH 来理解，但不能拿这个式子替代 BSIM 模型或可靠性检查。LED 的实际 Vf 会随电流改变，2.8 V 是 100 µA/27 °C 的锚定标签，不是固定电压源。 练习：暂按 Vf=2.8 V 手算：5 V→2.2 V 余量，2.9 V→0.1 V 余量。随后用 actual Vf 与电流核对，保留近似与仿真的差别。 条件：typical、27 °C、full-on；公式用于解释。

  • Vf 是 LED 在实际电流下的正向压降。
  • VDS,out 是输出 MOS drain 与 source 的电压。
  • 当前 VDS,out = VLED − Vf(ILED)。
  • 5 V nominal 下，actual Vf≈2.801 V，VDS≈2.199 V。
对照出处：headroom 推导 summary

13完整单像素电路：六个 MOS 各做一件事

能从器件表逐项核对完整 netlist。

原始 PDK 以 X subcircuit 调用，端序为 D、G、S、B，B 是 bulk/body。NMOS bulk 接 ground、PMOS bulk 接 vlogic 是当前 schematic 连接；到 layout 要实现 well/substrate ties。讲完读者应可以逐行读源码，并指出每个 net 去向。 条件：original nmos_6p0 / pmos_6p0；不是 full-PDK extracted netlist。

  • XREF 生成 bias，XOUT 从 LED 支路 sink 电流。
  • XPASS 导通时将 bias 传递到 gate。
  • XCLAMP 关断时释放 gate charge。
  • XINV_N 与 XINV_P 产生互补控制 pwm_b。
对照出处：pixel_driver.spice PDK lock

14On / Off 两个状态：为什么需要 gate clamp

预测 gate selection 的状态，并理解 off-state 放电。

Clamp 不是装饰，它主动移除 gate charge。开关放在 gate 控制支路，LED 导通路径只有一个 XOUT，保留 headroom。Inverter 有有限延迟，pass 与 clamp 可能短暂同时导通；这种现象要从 gate/bias/pwm_b 波形判断，不能凭平均值说边沿完美。NMOS pass 能否传递 bias 还受 threshold/body effect 影响。 条件：Vlogic=3.3 V、10 ns input slew。

  • PWM high：pass 开、clamp 关，gate 接近 bias。
  • PWM low：pass 关、clamp 开，gate 被拉低。
  • Gate 有电容；只断开连接可能留下电荷。
  • 边沿仍需检查 inverter delay、overlap 与 bias droop。
对照出处：gate selection 选择理由 edge CSV

15为什么第一版选 GF180MCU 6 V MOS

看懂工艺选择的需求与证据，而不是只记一个名称。

第一版工艺选择来自教学路径的电压域与器件需求，不是只记一个工艺名称。Phase 1 使用原始 nmos_6p0/pmos_6p0 model subset；当前物理流程使用完整 gf180mcuD，build hash为54435919abffb937387ec956209f9cf5fd2dfbee。Post-layout 的 schematic与RC提取网表都在这个 full PDK 下配对运行，不能把旧model subset与新版RC数值之差全归因于寄生。6 V器件标签不代表任意电压组合可靠或已达到foundry signoff。真实LED、IO与MPW要求仍可能改变最终选择。

  • 起始需求为 5 V LED supply、3.3 V control 与低侧 sink。
  • GF180MCU 公开模型提供 3.3 V / 6 V MOS。
  • Phase 1 原始 model subset 与完整 gf180mcuD 分别锁定。
  • Layout 与 post-layout 对比使用同一 full PDK，避免混合版本。
对照出处：Phase1模型锁定 full PDK和tool pin 物理回归模型边界 GF180 MOS device list

16把尺寸、供电和版本全部写出来

能从参数表重建当前设计，不依赖口头说明。

尺寸是 baseline 假设，尚未针对面积、速度、mismatch 或功耗优化。较长 L 常用于降低输出电压影响，也增加面积/电容；该趋势需以具体 sweep 量化。原始 model 用米表达 W/L，10u 是 10 µm，不能与某些 open_pdks wrapper 的 µm 单位约定混用。PMOS 4 µm 宽度是起始 sizing，不能直接称成最优或平衡 rise/fall。 条件：original model units；ideal current reference 未实现片上电路。

  • XREF / XOUT 的 W/L 为 10 / 2 µm。
  • Pass / clamp / inverter NMOS 为 2 / 1 µm，PMOS 为 4 / 1 µm。
  • VLED=5 V，Vlogic=3.3 V，external IREF=100 µA。
  • Model commit 与 SHA256 锁定，尺寸是公开 baseline 假设。
对照出处：driver netlist pdk-lock.json runner

17为什么先用 simple mirror，什么时候升级

将拓扑复杂度与具体问题对应起来。

第一版选择 six-MOS baseline 是为了能按器件学习并推进 layout。升级要由问题触发：例如 pre/post-layout 显示电流偏差大、低 duty settling 不足或阵列 reference fanout 过重，再设计相应改进。当前模型的 Vf 三点电流变化不大，不等于已经解决真实像素一致性。 条件：工程判断与教学趋势；非商业性能结论。

  • 电阻限流易理解，但对 Vf 与供电变化敏感。
  • Simple mirror 机制清楚，先暴露 output resistance 与 headroom。
  • Cascode 改善输出阻抗，需要更多 bias 与电压余量。
  • Current DAC 或 feedback 由明确精度和控制需求触发。
对照出处：baseline 比较 COCOA §5.3
Part 04

LED 模型与可复现实验

18Synthetic LED：公开假设比“像真的”更重要

认识模型包括什么、每个参数是什么。

这些参数由本项目独立设置，尚未拟合真实样品。CJO 不是所有偏压下固定 2 pF；TT 不是实测光学 rise time；EG 不能用于宣布材料颜色。当前无颜色、面积、current density、EQE、自热、aging 或封装参数。默认 Vf=2.8 V，变体 2.4/3.2 V 都是 synthetic load。 条件：所有 LED 参数均 synthetic。

  • 当前是独立定义、尚未实测拟合的 synthetic LED。
  • N=3、RS=50 Ω 描述合成 I-V 与串联压降。
  • CJO=2 pF、VJ=2.5 V、M=0.33、TT=1 ns 描述 charge 假设。
  • EG=2.6 eV、TNOM=27 °C；IS 按目标 Vf 计算。
对照出处：microled.spice ngspice 47 manual §7.2

19独立 DC 校准：先确认负载，再连接 driver

理解参数计算不等于 simulator 实际执行正确。

曾出现 N=2.2 时计算的 IS 过小、simulator 下限处理使不同 target 变为相同曲线的问题。干净日志无法替代独立 operating-point 检查。最终 N=3 是为了当前教育性模型与数值范围一致，不是从真实器件提取出的 ideality factor。DC 校准只证明本模型在一个规定点执行正确。 条件：27 °C / 100 µA；不证明全 I-V/温度范围。 先定义 VT=(k/q)T，再由 Vf=N·VT·ln(I/IS+1)+I·RS 反求 IS；I=100 µA、T=300.15 K。

  • 先用独立 100 µA DC source 验证 LED，不连接 mirror。
  • 27 °C 下分别核对 target Vf=2.4 / 2.8 / 3.2 V。
  • 数值容差为 0.1 mV，当前误差约 1 µV。
  • 接入 driver 后再次读取 actual Vf，避免只相信标签。
对照出处：led_calibration evidence led_is / calibrate_led 已记录的故障

21如何量电流：先定窗口，再按时间积分

能解释 average current 的分母和计算方式。

  • Adaptive samples 必须按时间加权，不能直接平均。

Regression Criteria

回归检查：数量、容差与结论要一起看

17 条件 × 2 variants = 34 次 transient，再对 RC variant 的 duty=1 / 64 各做一次 50 ns maximum timestep，总计 36 次 transient，加 3 次独立 LED DC calibration。19 guards = 17 个 paired-current guards + 2 个 RC timestep guards，全部通过。

检查组判据本次覆盖
Paired current|Irc − Ipre| ≤ max(1% × |Ipre|, 1 nA)17 条件；每例使用相同 full PDK 与相同输入
RC timestep convergence|I50ns − I200ns| ≤ max(0.2% × |I200ns|, 1 nA)仅 RC variant 的 duty=1 与 duty=64
Independent LED calibration|Vf_actual − Vf_target| < 0.1 mV100 µA / 27 °C；Vf = 2.4 / 2.8 / 3.2 V

为什么近零电流要有 absolute guard

在 off-state 或 disabled 条件下，reference 分母很小，直接看百分比容易误导。1 nA 的 absolute floor 是本教学回归的数值验收门槛；它避免把极小电流的相对变化放大为严重误差。这个门槛不是已测量的产品 leakage 规格。
