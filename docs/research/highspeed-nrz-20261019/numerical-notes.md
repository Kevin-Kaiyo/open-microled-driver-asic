# NRZ 瞬态仿真的数值收敛诊断

本节记录实际失败、隔离方法与复现实验。日期：2026-10-19。它用于说明正式比较的积分算法和容差设定；不将求解器收敛等同于芯片性能通过验证。

## 发生了什么

首轮路线 A 在 1 Gb/s、20 ps 输入边沿下使用梯形积分（trapezoidal integration），在约 127 ns 的 PWL 输入转换处终止。原始日志记录：

```text
Timestep too small; time = 1.27e-07, timestep = 3.125e-23
trouble with node "vdata#branch"
```

该次运行返回退出码 0，并留下未完成的波形。因此，只检查进程退出码不足以判断仿真成功：还必须检查错误日志和最终时间是否到达计划终点。

失败前最后一个时间点约为 127.000000042667 ns，输入电压仅约 7.04 uV，正处在斜坡开始处。输入电流包含 MOS 栅电容的位移电流。这个现象提示需要检查 PWL 斜率突变附近的数值积分与电荷差分，而不能直接解释成电路在 127 ns 发生物理失效。

## 如何隔离原因

诊断使用首轮冻结的网表和模型，只改变积分算法、最大步长或时间戳表示。保持 MOS、静态 LED 曲线、200 fF 假设电容、1 ohm / 0.5 nH 封装假设、20 ps 输入边沿及求解容差不变。所有失败日志和原始波形均保留在 `build/highspeed-nrz/pwl-debug/`。

| 诊断副本 | 改动 | 到达计划终点 |
|---|---|---|
| 原始梯形积分，140 ns 终点 | 无 | 否；仍在约 127 ns 失败 |
| Gear 积分，140 ns 终点 | 仅改变积分方法，默认二阶 | 是 |
| 梯形积分，140 ns 终点 | PWL 时间戳由 16 位规范为 12 位有效数字 | 是 |
| 梯形积分，140 ns 终点 | 最大步长由 25 ps 减至 5 ps | 是 |
| 二阶 Gear，完整 829 ns 终点 | `method=gear maxord=2`，保留原 16 位时间戳 | 是；494,764 行 |
| 梯形积分，完整 829 ns 终点 | 仅规范为 12 位时间戳 | 否；失败移至约 202 ns |

因此，规范化时间戳可减少浮点表示中的无意义尾数，但**单独舍入时间戳不能可靠解决问题**。二阶 Gear 在这个完整序列上成功，且需要与成功的细步长梯形积分对照，确认其数值阻尼没有显著改变关心的物理量。

## 结果是否被积分方法改变

路线 A 比较窗为 **32–120 ns，共 88 bit**。这是一段专用于数值诊断的共同窗口，不是正式验证集。能量统计包含 VLED、VDD、VH、VL 的外部端子；不包含理想 DATA 源和实际稳压器损耗。

| 算法 | 有符号能量 fJ/bit | 正向供能 fJ/bit | 导电 LED 电流相对细步长梯形积分的 RMS 差异 |
|---|---:|---:|---:|
| 梯形积分，12 位时间戳 | 382.394 | 552.606 | 0.00130 uA |
| 二阶 Gear | 382.375 | 551.661 | 0.00415 uA |
| 梯形积分，5 ps 最大步长 | 382.394 | 552.794 | 参考值 |

Gear 与细步长梯形积分的有符号能量差约 **0.005%**，正向供能差约 **0.205%**。电流 RMS 差异采用共同的 0.5 ps 显示/比较网格作线性插值；插值不增加原仿真的带宽或独立采样证据。

额外检查了首轮路线 B 的 0.5 Gb/s、200 ns 片段。在 64–200 ns 的共同窗口内，梯形积分与 Gear 的有符号能量分别为 1063.808 和 1063.804 fJ/bit，LED 导电电流 RMS 差异约 0.00501 uA。总行数仅从 315,703 减少到 303,779，因此不能把路线 B 的大量时间步全部归因为梯形积分数值振铃。此处 B 仍使用首轮的 0.35 um 扩散延伸假设，只作求解器诊断，不参与正式的统一几何比较。

## 高频复查：二阶 Gear 本身还不充分

后续严格容差实验中，二阶 Gear 在 A/2 Gb/s 的约 259 ns、A/4 Gb/s 的约 6.75 ns 仍然失败。不能将这些求解失败记成电路或链路的速率不通过。进一步使用独立副本检查：只增加 1 ohm 输入源电阻、只减小最大步长至 1 ps，或只调整电流绝对容差，都没有稳定解决问题。只把 `chgtol` 改为 `1e-16` 可将 A/4 Gb/s 的失败推迟至 202.75 ns，但尚未达到 207.25 ns 终点。

在不改变任何电路、供电、负载、速率或输入边沿的情况下，采用以下数值设定后，A 的 1、2、4、8 Gb/s 均完成全序列：

```spice
.options reltol=1e-5 abstol=1e-13 vntol=1e-7 chgtol=1e-16 method=gear maxord=2
```

这涉及数值容差调整，因此必须量化与严格解、细化步长解的差别，不能只凭“跑完”接受结果。比较仍在相同输入序列的 511 bit 窗口内进行：1 Gb/s 为 286–797 ns，4 Gb/s 为 71.5–199.25 ns。

| 检查 | 正向供能 fJ/bit | 相对变化 | LED 导电电流 RMS 差异 | 接收代理输出 RMS 差异 |
|---|---:|---:|---:|---:|
| A/1 Gb/s，原严格 Gear 解 | 585.875 | 参考 | 参考 | 参考 |
| A/1 Gb/s，建议容差 | 585.792 | −0.01423% | 0.01685 uA | 0.009623 uA |
| A/4 Gb/s，建议容差，最大步长 6.25 ps | 322.651 | 参考 | 参考 | 参考 |
| A/4 Gb/s，建议容差，最大步长 1 ps | 322.659 | +0.00246% | 0.003744 uA | 0.001977 uA |

接收代理仍是报告声明的相同一阶光学/接收低通假设；这些 RMS 差异只用于数值一致性检查，不代表实测噪声或 BER。默认比较保留较严格的 `reltol=1e-5`，没有采用这里另外测试的 `1e-4` 或常见默认 `1e-3` 作为最终方案。

## 结论与复现

这些实验支持“PWL 转换附近、对积分方法与容差敏感的数值收敛问题”这一解释，但尚未定位 ngspice 内部的某项具体实现缺陷。正式研究采用统一二阶 Gear 与上列容差，并保留严格容差、细化步长与梯形积分对照；电路与负载条件保持原样。

精简证据、每份网表/日志/原始波形的 SHA-256、比较窗口及软件版本保存在：

- `evidence/highspeed-nrz/numerical-diagnosis.json`
- 原始失败：`build/highspeed-nrz/run-7bl7j0yj/cases/A-nominal-1G-typical-27C-3.3V-C200-L0.5-e20-s40/ngspice.log`
- 复现脚本：`build/highspeed-nrz/pwl-debug/diagnose.py`

为保留证据并减少磁盘占用，本次新建诊断目录中的 `waveform.dat` 已逐个压缩为 `.dat.gz`。每份文件都在压缩后完整解压回读并核对原始字节 SHA-256，通过后才移除未压缩副本。证据同时保留原始字节哈希与归档文件路径/哈希；分析脚本可直接读取 gzip，无需展开成新的原始文件。

```sh
# 重新计算保留波形的指标
build/layout/venv/bin/python build/highspeed-nrz/pwl-debug/diagnose.py

# 使用保留的诊断网表重新运行，再计算指标
build/layout/venv/bin/python build/highspeed-nrz/pwl-debug/diagnose.py --rerun
```

数值诊断通过不建立实测光学带宽、BER、PEX、版图或流片结论。
