# 新驱动方法与产品落地 Implementation Plan

> 执行方式：并行研究、独立科学审查、阶段交付。用户已授权在 A/B 双主线及 VCSEL 上继续不同技术方法；日常试验选择由本轮研究决定，不请求重复确认。

**Goal:** 实际验证不同提速和降能耗机制，解释物理原因与失败条件，形成现有技术报告的第二版，并明确产品与流片所需证据。

**Architecture:** 以 2026-11-11 第一版冻结候选为基线，新增独立运行目录、网表、执行快照和哈希。不把改变光学/RX 假设称为 Driver 电路改善。保持 A/B 并行，VCSEL 独立预算。

**Tech Stack:** GF180 公共模型子集、ngspice 47 KLU、Python 3.12、现有原生能量/器件应力/训练接收工具、Matplotlib、ReportLab 与 PDF/HTML 验证。

**Spec:** 本轮用户要求，以及第一版 `docs/research/driver-improvement-20261111/README.md` 的冻结条件和未完成事项。

## 固定条件与范围

- A/B：20 µm 黄光静态参考，200 fF，1 Ω/0.5 nH，25/100 µA；主比较保持 200 ps 光学时间常数与 1 GHz RX。VCSEL：850 nm 研究模型、150 fF、0.5 Ω/0.2 nH、3/7 mA、原光学代理与5 GHz RX。
- 净/线速率=32/37，4096验证载荷位；相位只由训练段选择；零训练/验证错误、幅度≥7.5 µAeq、单侧时间≥0.37 bit UI；额外检查DC匹配、全部器件应力与模型域。
- 能量覆盖实际实例化的全部供电/数据端口，保留正向、返回和净值，报告有限帧及初始储能边界。失败点不作有效载荷能效排名。
- 仅两路并发 ngspice。失败必须保留，不无限堆叠改动。最终候选冻结后做半步长和另一段数据序列；如果没有通过，则如实保留失败结论。
- 不修改上一版运行证据；不继承旧 DRC/LVS/PEX，不预先声称蓝光、实测 BER、连续工作、产品或流片合格。

## 选择与技术假设

1. A/B 的低压供电、虚支路及瞬态电荷管理：优先测试有可解释能耗来源的不同机制，允许名义DC重新匹配但不得按每个码型或速率调参。最终具体矩阵记录于新候选 manifest。
2. VCSEL 的频率响应整形与实际供电：分别做单项对照，复查导通压降、门极负载、峰值电流及可用摆幅，保留既有参考与保护路径的真实开销。
3. 光学/RX 假设的二维敏感性：复用已验真原生电流，对光学时间常数与接收带宽作单独标记的后处理。它用于确定器件/接收需求；不代表实现了新发光器件或新接收器。

## 审查重点

电源变更后的真实压降和DC偏差；名义匹配不等于PVT；保护期间旁路注入；新增电容的初始储能；只改善模型假设而未改变硬件；短帧零错不等于BER；没有匹配完整PDK的物理结果不可进入流片签核。
